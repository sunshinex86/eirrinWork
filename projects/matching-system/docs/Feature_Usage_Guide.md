# 機能使用参照手順

> 作成日: 2026-08-05
> 目的: 本システムの各機能について「画面（Streamlit UI）」と「Claude Code の MCP Server」のどちらから使えるかを整理し、MCP 経由で質問する際の例文を示す。

## 1. 全体像

本システムには機能を使う経路が2つある。

| 経路 | 特徴 |
|---|---|
| 画面（Streamlit UI） | ブラウザで操作。データの**新規登録・更新・削除（CRUD）**を含む全機能が使える |
| Claude Code MCP Server（`matching-system`） | Claude Code のチャットで自然言語のまま質問し、ツールを呼び出す。**参照・計算系のみ**（読み取り専用） |

MCP サーバーの起動確認: `claude mcp list` で `matching-system: python mcp_server.py - ✔ Connected` と表示されていればOK。

### 使い分けの原則

- **データの登録・編集・削除・サンプル読込 → 必ず画面から行う**
  MCP に公開されている15個のツールは全て `readOnlyHint: True`（読み取り専用）であり、書き込み系の操作は存在しない。
- **マッチング計算・スキル検索・ギャップ分析・推薦理由・JD最適化・スケジュール判定などの「調べる・計算する」系 → 画面でもMCPでもどちらでも可能**
  画面は結果をグラフィカルに確認したい場合、MCPは会話の流れの中でサッと聞きたい場合に向いている。

## 2. 画面（Streamlit UI）でしかできない機能

| 画面 | ファイル | できること |
|---|---|---|
| 📋 経歴書管理 | `01_経歴書管理.py` | 経歴書の新規登録／削除、サンプルデータ一括読込、未解決スキルの新規登録・紐付け・無視 |
| 📌 案件管理 | `02_案件管理.py` | 案件の新規登録／削除、サンプルデータ一括読込、未解決スキルの新規登録・紐付け・無視 |
| 🛠️ スキル管理 | `04_スキル管理.py` | スキルの新規登録・更新・削除（論理削除）、スキル階層の整合性検証 |
| 🗓️ スケジュール（一部） | `05_スケジュール.py` | 複数候補者の横並びランキング表示、比較カードのビジュアル表示 |

※ マッチング画面（`03_マッチング.py`）自体は MCP と同じ計算処理（`compute_hybrid_score` 等）を呼んでいるため、後述のMCPツールと機能的に重複する。グラフィカルに一覧・詳細を見たい時は画面、チャットでサッと聞きたい時はMCP、という使い分けでよい。

## 3. Claude Code（MCP）から直接質問できる機能

MCPサーバー名: `matching-system`（実体: `mcp_server.py`）

| ツール名 | 機能概要 | こう聞ける例 |
|---|---|---|
| `matching_score` | 経歴書1件×案件1件のマッチングスコアを計算（hybrid / keyword / semantic を選択可） | 「resume-001とjob-005のマッチ度を教えて」 |
| `resume_job_matches` **（新規追加）** | 経歴書1件に対して**全案件**のスコア・一致スキル・不足スキルを一括取得（1回の呼び出しで完結、高速） | 「田中太郎さんと相性が良い案件はどれ？スコアと足りない技術も教えて」 |
| `search_skills` | スキル辞書を部分一致検索 | 「スキル辞書にKubernetes関連のスキルは何がある？」 |
| `get_skill_context` | 特定スキルに紐づく業界知識・ロール情報をナレッジベースから取得 | 「AWSというスキルはどんな業界・ロールで使われる？」 |
| `search_knowledge` | ナレッジベースをキーワード検索 | 「ナレッジベースで“派遣契約”について調べて」 |
| `analyze_skill_gap` | 経歴書×案件のスキルギャップ（一致／不足／余剰）を分析 | 「resume-002はjob-003に対してどのスキルが足りない？」 |
| `extract_skills` | 自由記述テキストからスキルを抽出 | 「この自己紹介文からスキルを抽出して：〇〇〇〇」 |
| `recommendation_reason` | 候補者×案件の推薦理由をスキル・業界・経験の観点で分解 | 「なぜresume-001をjob-001に推薦するのか理由を教えて」 |
| `optimize_jd` | JD（求人票）文章を自動最適化し、技能抽出と予算妥当性を判定 | 「このJD文章を最適化して、技能抽出と予算感もチェックして：〇〇〇〇」 |
| `recommendation_actions` | 候補者に対する推薦順位・連絡優先度・自動コミュニケーション文を生成 | 「田中太郎さんに対する推薦アクションを5件、連絡文つきで教えて」 |
| `schedule_availability` | 候補者の稼働可能時間と案件の希望時間帯をモデリングして一致度判定 | 「この候補者は案件の希望時間帯に対応できる？」 |
| `schedule_conflicts` | 候補者のスケジュールと他イベントの競合を検知 | 「この候補者のスケジュールに他の予定との競合はある？」 |
| `market_skill_supply_demand` **（新規追加）** | スキル別の需要案件数と保有経歴書数を比較し、需給バランス（scarce/balanced/surplus）を判定 | 「今年に入ってからAWSスキルは需要過多になっている？」 |
| `market_unit_price_trend` **（新規追加）** | 月次の単価（平均・中央値）推移を集計、スキルや職種で絞り込み可能 | 「Pythonエンジニアの単価は直近半年でどう推移してる？」 |
| `market_tech_trend` **（新規追加）** | 月次のスキル出現頻度から上昇・下降トレンドを抽出 | 「今年、案件で需要が伸びている技術トップ5を教えて」 |

## 4. 注意事項

- **MCPツールは全て読み取り専用。** 経歴書・案件・スキルの登録／編集／削除は必ず画面から行うこと。
- **`mcp_server.py` はセッション開始時に起動する長時間駐在プロセス。** ツールを追加・修正しても、Claude Code を再起動（またはMCP再接続）するまで反映されない。
- **同一MCPサーバーへの同時並列呼び出しは詰まる場合がある。** 実測で `matching_score` を5件同時に呼んだところ、1件は数十ミリ秒で返ったが、残り4件は47分後にタイムアウトして失敗した（stdio接続がシリアルにしか処理できないことが原因と推測）。複数案件・複数経歴書をまとめて調べたい時は、`resume_job_matches` のような「1回の呼び出しで全件処理する」ツールを使うか、逐次（直列）で呼び出すこと。
